# Доказательство до «проверь»

Пользователь — дизайнер и проверяет каждую UI-правку руками. Когда правку
приносят без доказательства, круги «всё равно не так» тянутся долго: у пилюли
таймера их было около пятнадцати, у морфа переводчика — около десяти. Каждый
такой круг стоит пользователю пересборки и проверки. Поэтому сначала Claude
сам смотрит на результат и меряет его, а уже потом пишет «готово».

## 1. Найти образец до того, как писать контрол

Новая кнопка, поле, сегмент или меню почти всегда уже где-то есть. Двенадцать
раз пользователь писал «не пиши с нуля, переиспользуй» — каждый раз из-за
контрола, собранного заново, который потом расходился с соседями по высоте или
отступам.

- Если пользователь сказал «как у X», то X и есть образец. Найди, где X собран,
  и используй тот же тип.
- Общие контролы:
  - `Stampo/PanelButtons.swift` — `PanelIconButton`, `PanelMoreMenuButton`,
    `PanelButtonStyle`, `PanelPopUpButton`;
  - `Stampo/Editor/NumberField.swift` — числовые поля оформления;
  - `Stampo/Editor/UniformSegmentedPicker.swift` — сегменты
    (`UniformSegmentedPicker`, `UniformSegmentedToggles`);
  - `Stampo/Editor/GradientStopsBar.swift` — `ColorField`;
  - `Stampo/Editor/ActiveToolChrome.swift` — включённое состояние инструмента;
  - `Stampo/SettingRow.swift`, `Stampo/SettingsPickers.swift` — настройки.
- Каталог `Docs/Stampo/ui-elements.md` устарел (апрель, ещё «Tray»), на него
  не опираться.
- Если аналога действительно нет, скажи об этом в ответе, а не молча собирай
  новый.

## 2. Снять и замерить

Временный пробник — тест-сьют в `StampoTests/`, который показывает настоящий
вид на экране и снимает его:

```swift
@MainActor @Suite struct FieldHeightProbe {          // временный, удалить после
    @Test func fields() throws {
        let window = Probe.onScreen(SomeView(...), size: NSSize(width: 340, height: 900))
        defer { window.orderOut(nil) }
        let png = try Probe.shoot(window, "fields")   // печатает PROBE /tmp/stampo-probes/fields.png
        let bitmap = try Probe.bitmap(png)            // bitmap[x:, y:] — RGBA, y сверху
        // мерить: высоты контрола и образца, зазоры, базовые линии
    }
}
```

- Посмотри на PNG через Read, а нужные числа получи из `Probe.bitmap`, не на
  глаз. Новый контрол и образец снимай в одном кадре и сравнивай их размеры.
- Снимок идёт в двойном масштабе Retina: пиксели делить на
  `window.backingScaleFactor`, чтобы получить pt.
- `cacheDisplay` и `layer.render(in:)` теряют текст и SF Symbols. Поэтому
  `Probe.shoot` снимает окно через `screencapture -l`.
- Рамка из `GeometryReader` — это не нарисованный безель. Если вопрос визуальный
  («одинаковая ли высота»), мерь пиксели.
- Проверь, что диапазон строк, который ты сканируешь, действительно накрывает
  нужную полосу. Однажды замер попал в заголовок панели вместо плашек и
  «доказал» равенство, которого не было.
- Вид, который появляется только в переходном состоянии (дроп-плашка во время
  перетаскивания), можно снять, если временно форсировать условие пометкой
  `// PROBE` (`.opacity(1) // PROBE`). Потом вернуть.

## 3. Анимация — покадрово

Анимацию нельзя проверить рассуждением. Её надо заснять и посмотреть по кадрам.

- **SwiftUI** (морфы панели, фейды, появление текста) — `Probe.film`:
  ```swift
  @Test func morph() async throws {
      let window = Probe.onScreen(view, size: NSSize(width: 560, height: 260))
      defer { window.orderOut(nil) }
      try await Probe.film(window, "morph", seconds: 1.2) {
          withAnimation(...) { model.change() }        // то же изменение, что в приложении
      }
      // PROBE /tmp/stampo-probes/morph-storyboard.png · 45 frames at 30 fps … · the change lands near frame 10
  }
  ```
  Фильм пишется в реальном времени через `screencapture -v`, затем режется на
  кадры (`/tmp/stampo-probes/morph/001.png…`) и собирается в раскадровку:
  кадры идут слева направо и сверху вниз. Остановленные часы слоя SwiftUI-анимации
  не держат, поэтому для них нужна живая запись.
- **Core Animation** (маскот, слои) — остановленные часы слоя: `stop` / `tick` /
  `frames` в `StampoTests/MascotViewTests.swift`. Это детерминированно и без
  `Task.sleep`. Трансформации проверяй ещё и числами из
  `presentation()?.value(forKeyPath:)`: пружинное появление на кадрах может
  не проявиться.
- Ответ даётся на вопрос пользователя с номерами кадров: «текст начинает
  проявляться на кадре 14, морф закончился на 12». Не «вроде плавно».

## 4. Хит-зоны

Хит-тест нельзя выводить рассуждением. SwiftUI заворачивает AppKit-вид в
неперевёрнутый `PlatformViewHost`, приложение же перевёрнуто, и точка
отражается. Проверяй сеткой hit-test в координатах окна, как в
`StampoTests/ArchiveCellHitTests.swift`. Добавь контрольную проверку с
противоположным ожидаемым ответом: перевёрнутый пробник проходит и ничего не
показывает.

## 5. Как запускать пробник

```bash
xcodebuild test -project Stampo.xcodeproj -scheme Stampo -destination 'platform=macOS' \
  -parallel-testing-enabled NO '-only-testing:StampoTests/FieldHeightProbe'
```

- **Не через `Scripts/run-tests.sh`.** Он подписывает тестовое приложение ad-hoc.
  У такой копии нет разрешения на запись экрана, и `screencapture` выходит с
  кодом 1. Обычная подпись проекта разрешение сохраняет.
- `-parallel-testing-enabled NO` обязателен: без него прогон виснет на
  «waiting for workers».
- Один тест из Swift Testing выбирается со скобками:
  `'-only-testing:StampoTests/FieldHeightProbe/fields()'`. Без скобок
  выполняется 0 тестов, и прогон выглядит зелёным.

## 6. Показать пользователю

В сообщении «готово»:
- скриншот или раскадровка через SendUserFile;
- одна-две строки замера: «высота поля 28 pt, как у «Холста»; зазор 6 pt»;
- отдельным списком — что замером не проверить и нужно проверить руками: ввод с
  клавиатуры, жесты, модификаторы, разрешения, поведение на экране с чёлкой и без.
  Для этого собрать и запустить приложение через `bash Scripts/run-dev.sh` и
  привести строку `Running: …` из его вывода.

## 7. Гигиена пробника

- Пробник не трогает настоящий `NotchArchiveModel`: `add(color:)` и
  `add(text:)` через 0,3 с пишут в настоящий архив пользователя. Снимай пустую
  модель или демо-данные.
- Настройки — только через `AppSettings.store`. Под тестами это отдельный
  домен; `UserDefaults.standard` в хостед-тесте — настоящие настройки
  пользователя.
- В пробнике ждать асинхронный код приложения надо через `try await Task.sleep`
  в цикле, а не прокачкой `RunLoop.main.run`: `@MainActor`-таск тогда не
  выполнится. `RunLoop` годится только для ожидания вёрстки, и `Probe.onScreen`
  уже делает это сам.
- Кнопку SwiftUI со стилем `.plain` или `.borderlessButton` из пробника не
  нажать: в дереве у неё нет заголовка. Правило, которое срабатывает по нажатию,
  вынеси в чистую функцию и покрой её тестом.
- После проверки удали пробник и уберись: `git status` должен показывать только
  настоящую правку, без `// PROBE` в коде. Если после удаления тест-файла
  `xcodebuild test` падает с `CodeSign failed / code object is not signed at all`,
  лечится это `xcodebuild clean`. Ценный пробник можно оставить по образцу
  `StampoTests/Mascot*Probe.swift`.
