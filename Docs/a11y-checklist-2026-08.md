# Чек-лист ручной проверки — доступность, август 2026

Покрывает ветку `accessibility-keyboard-and-voiceover`: клавиатурный доступ
к рекордеру шоткатов (`e625063`), увеличенный контраст (`abfd0f5`),
ленивая полоса архива (`9b378c0`), Esc в онбординге.

**Поддержка VoiceOver снята с этой ветки** и припаркована в
`voiceover-support` — см. `backlog.md`. Разделы про озвучивание убраны
отсюда вместе с ней.

Автотестами это не закрывается: всё ниже требует реальных событий клавиатуры
и живого VoiceOver.

---

## 0. Подготовка

- [ ] Запущена **свежая сборка этого чекаута**. Копий `Stampo.app` на машине
      несколько (DerivedData основного чекаута, DerivedData каждого воркtree,
      `build/export`, архив, `/Applications`), все с одним bundle id, поэтому
      закрыть текущую и запустить нужную по полному пути:

      ```
      DD=$(ls -d ~/Library/Developer/Xcode/DerivedData/Stampo-* | while read d; do
             plutil -p "$d/info.plist" | grep -q "xcode/Stampo/Stampo.xcodeproj" && echo "$d"; done | head -1)
      osascript -e 'quit app id "com.hex000.Stampo"'
      open "$DD/Build/Products/Debug/Stampo.app"
      ps -Ao args | grep "Stampo.app" | grep -v grep
      ```

      Путь в выводе `ps` должен совпадать с `$DD`. Проверять это обязательно:
      `open` на уже запущенном приложении не перезапускает его, а просто
      выводит вперёд, и правки «не появляются». Один раз здесь всплыла и
      сборка из воркtree с тем же bundle id.
      После проверки вернуть обычную версию: тот же `quit`, затем
      `open /Applications/Stampo.app`.
- [ ] **System Settings → Keyboard → Keyboard navigation — включено.**
      Без этого Tab не доходит до кнопок и нетекстовых контролов, и пункт 1
      будет выглядеть сломанным, хотя сломана настройка.
---

## 1. Рекордер шоткатов — главное, ради чего всё затевалось

Settings → Shortcuts.

- [ ] **Tab доходит до поля записи.** Вокруг поля появляется акцентный ореол,
      рамка при этом остаётся серой.
- [ ] **Space взводит запись.** Появляется «Нажмите клавиши…», рамка становится
      акцентной. Ореол фокуса при этом остаётся — состояний два и они различимы.
- [ ] **Return взводит запись** так же, как Space.
- [ ] **Комбинация назначается с клавиатуры**: взвести → нажать ⌥⌘9 → поле
      показывает новые кнопки-капсы, запись закрывается.
- [ ] **Escape отменяет запись**, комбинация не меняется. Фокус остаётся на поле.
- [ ] **Невалидная комбинация** (например, одна буква без модификатора) — поле
      дёргается, показывает причину, остаётся взведённым.
- [ ] **Tab со взведённого поля** снимает запись: перейти на соседний контрол и
      убедиться, что клавиши снова печатаются нормально (например, ⌘W закрывает
      окно, а не проглатывается монитором). Это самая важная проверка из всех:
      монитор глобальный, зависший — ловит клавиши всего приложения.
- [ ] Клик мышью по полю по-прежнему взводит и снимает запись.
- [ ] Клик мимо поля отменяет запись (старое поведение не сломано).

## 2. Редактор

Открыть редактор: снять скриншот и кликнуть по превью, которое появится
внизу экрана.

- [ ] Наведение на кнопку тулбара по-прежнему показывает тултип **с шоткатом**
      в скобках: «Копировать (⌘C)».

## 3. Увеличенный контраст

System Settings → Accessibility → Display → **Increase contrast**.

Что значение вообще доходит до панели — **проверено замером** 2026-08-06:
вью внутри такого же borderless non-activating `NSPanel` на уровне статус-бара
читает `colorSchemeContrast` как `increased` наравне с обычным окном. Это было
главное сомнение (отсоединённое окно могло не получать системное значение), и
его перепроверять не нужно. Ниже — только то, что решается глазом.

- [ ] С **выключенной** настройкой панель выглядит ровно как раньше. Это
      гарантировано кодом (ветка standard возвращает прежнее значение
      буквально), так что достаточно беглого взгляда.
- [ ] С **включённой**: hover, нажатие и активное состояние кнопок панели
      заметно отличаются от покоя, а не на несколько процентов альфы.
- [ ] Пять состояний не слиплись в одно белое пятно — порядок
      «покой → hover → активно → нажато» по-прежнему читается.
- [ ] Иконки и подписи в панели становятся полностью белыми.
- [ ] Обводка ячеек архива под курсором заметно сильнее, чем без него.
- [ ] Кольцо обратного отсчёта: дорожка и заполнение различимы.

## 4. Онбординг

- [ ] Settings → General → Introduction → Show… → **Escape закрывает окно.**
- [ ] Return по-прежнему нажимает основную кнопку.
- [ ] Закрытие по Esc не ломает последующее поведение: панель открывается,
      настройки открываются, повторный показ онбординга работает.

## 5. Регрессии

- [ ] **Русская локаль**: переключить App language → Русский, пройти настройки
      глазами. Ни одна строка не должна отображаться как английский ключ.
- [ ] Раскладка настроек не поехала: степпер компактный, пикеры не разъехались,
      подписи контролов нигде не проступили на экран.
- [ ] Тёмная и светлая темы — ореол фокуса рекордера виден в обеих.
- [ ] Проверить при системном акцентном цвете, отличном от синего (ореол
      завязан на `Color.accentColor`).

## 6. Заведомо не покрыто этими коммитами

Не искать здесь — это осознанно отложено:

- **#4** Reduce Motion — пропущено по решению.
- **#1, #3, #6, #7, #8, #9, #15** — вся работа по VoiceOver снята с ветки
  и припаркована в `voiceover-support`, см. `backlog.md`.
- **#10** клавиатурная навигация в редакторе — снята с ветки и
  припаркована, см. `backlog.md`.
- **#17** масштабирование key caps — **отклонено по результатам замера**, а не
  отложено. На macOS `dynamicTypeSize` не влияет на эту вёрстку вообще:
  подпись строки при `.large` и при `.accessibility3` дала одинаковые 24px
  высоты и 344px ширины. Рассинхрона между капсами и текстом, о котором
  говорило ревью, не существует — масштабировать капсы означало бы
  подстраиваться под сигнал, которого нет.
- **#12** подтверждение на удаление в редакторе, **#14** размеры иконок,
  **#16** и **#18** — отклонены при разборе ревью.
